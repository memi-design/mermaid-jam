# Distribution Plan

The repo is public, but discovery comes from repeated proof: screenshots, examples, short clips, and clear use cases.

## Core Positioning

Mermaid Jam is for people who like diagrams-as-code but need editable FigJam boards.

Primary promise:

```text
Paste Mermaid or markdown. Generate editable FigJam userflows.
```

Secondary promise:

```text
Local-only, no accounts, no analytics, no backend.
```

## First 48 Hours

1. Publish the Figma Community listing.
2. Pin the GitHub repo on the `sarveshsea` profile.
3. Add the GitHub Pages link to the repo homepage.
4. Post the short launch copy from `docs/LAUNCH.md` on X/LinkedIn.
5. Share one concrete before/after: Mermaid source on the left, editable FigJam board on the right.
6. Ask 5 design/product friends to try one pasted Mermaid flow and give feedback.
7. Open 3 public roadmap issues so visitors see direction.

## First Week

1. Record a 20-30 second screen capture: paste source, generate, drag node, update.
2. Add the clip to Figma Community and social posts.
3. Submit to relevant communities:
   - Figma Community comments and creator network.
   - Mermaid.js community channels.
   - Product/design Slack or Discord groups.
   - Indie Hackers build-in-public.
   - Hacker News Show HN once the Figma listing is live.
4. Ask users for broken Mermaid examples and turn them into tests.
5. Ship one small release from feedback within 7 days.

## Repo Conversion Checklist

- README has a one-line value prop above the fold.
- README has badges for CI, release, license, and Figma Community.
- Examples are copy-pasteable.
- GitHub Pages landing page exists.
- Issues and Discussions are enabled.
- Labels exist for parser, layout, renderer, UI, docs, good first issue.
- CI passes on every push and PR.
- Release assets include `manifest.json`, `code.js`, and `ui.html`.
